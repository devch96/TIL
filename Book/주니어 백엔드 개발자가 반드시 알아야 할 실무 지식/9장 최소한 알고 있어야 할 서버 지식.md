## OS 계정과 권한

- root 계정은 OS를 설치하면 기본 생성되는 계정으로 모든 권한을 가진 관리자 계정
  - 보통 인프라 담당자만 root 계정 접근 권한을 갖고 나머지 개발자는 별도로 생성한 사용자 계정을 이용해 서버에 연결
- 리눅스는 계정과 함께 그룹 개념도 사용함
  - 여러 계정을 하나의 그룹으로 묶어 권한을 관리할 수 있음
- 특정 파일을 실행했는데 접근이 거부된 메시지를 받는다면 실행에 필요한 권한이 없는 것
- 파일을 실행할 때 접근 거부가 발생하는 이유는 보통 읽기 권한이나 실행 권한이 없기 때문
  - ls -l 명령어를 사용하면 파일 권한을 포함한 여러 정보를 사용할 수 있음
  - rw-r--r--
  - rwxr--r--
- 파일 권한 부분은 첫 세 글자가 소유자의 권한, 중간 세 글자가 그룹의 권한, 마지막 세 글자가 다른 사용자에 대한 권한을 표시한다
- r,w,x 는 read(읽기), write(쓰기), eXecute(실행) 권한이다
- rwxr--r--
  - 소유자
    - 읽기, 쓰기, 실행
  - 그룹
    - 읽기
  - 다른 계정
    - 읽기
- 권한은 숫자로도 표현함
  - r(읽기): 4
  - w(쓰기): 2
  - x(실행): 1
- chmod로 권한을 변경할 때는 숫자 합을 이용할 수 있음
  - 읽기와 쓰기 권한 부여
    - 6
  - 전체 권한(읽기, 쓰기, 실행)
    - 7
  - 습관적으로 chmod 777을 사용하면 안됨(모든 권한이 다 열리기 때문에 보안 취약)
- 숫자 대신 개별 항목에 대해 권한을 지정할 수 있음
  - chmod u+x run.sh
    - 소유자(u)에게 실행(x)권한을 추가
  - 소유자(u), 그룹(g), 다른 사용자(o), 모두(a)
  - 추가(+), 제거(-), 지정(=)
  - 읽기(r), 쓰기(w), 실행(x)

### sudo로 권한 주기

- root 권한이 필요할 때마다 매번 인프라 담당자한테 작업을 요청하면 업무 효율이 떨어짐
- root 권한을 개별 계정에게 부여하면 보안 측면에서 위험함
- sudo 명령어는 다른 사용자의 권한으로 프로그램을 실행할 수 있음
- sudo 명령어와 관련된 설정은 /etc/sudoers/ 파일이나 /etc/sudoers.d 디렉토리에 위치한 파일로 관리함
  - root ALL=(ALL) ALL
    - root 계정은 모든 호스트에 대해 (ALL) 모든 사용자로 ALL 모든 명령어를 사용할 수 있음
  - user1 계정에 sudo로 모든 명령어를 실행할 수 있게 하려면 user1 ALL=(ALL) ALL
  - visudo 명령어를 사용하면 쉽게 편집 가능
    - sudoers 파일은 읽기 전용 파일이기 때문에 vi로 수정하면 sudoers 파일의 권한을 수정 전/후에 변경해야 하는데 visudo 명령어를 사용하면
    편하게 수정할 수 있음
- 만약 암호 없이 바로 실행할 수 있기를 원한다면 NOPASSWD: 설정을 추가하면 됨
  - user1 ALL=(ALL) NOPASSWD: ALL
- 하지만 암호 없이 sudo로 모든 명령어를 실행한다는건 root 암호를 알려준 것이나 다름 없음
- 그래서 ALL 대신에 특정 명령어만 실행할 수 있는 권한을 부여함
  - user1 ALL=(ALL) NOPASSWD: /usr/bin/systemctl
- 명령어 뒤에 인자를 추가해서 해당 인자를 사용한 명령만 허용할 수도 있음
  - user1 ALL=(ALL) NOPASSWD: /usr/bin/systemctl start docker
  - user1 ALL=(ALL) NOPASSWD: /usr/bin/systemctl stop docker

## 프로세스 확인하기

- 프로세스 ID를 확인하여 프로세스를 종료시켜야 하는 상황이 있다
  - ps aux
  - ps -eaf
- 프로세스가 사용하는 cpu나 메모리 사용량을 실시간으로 확인할 때에는 top이나 top을 개선한 htop 같은 프로그램을 사용한다

```shell
ps aux --sort -rss | head -n 6
```

### 프로세스 종료

- 프로세스를 종료할 때는 kill 명령어를 사용
- 명령행 인자로 프로세스 ID를 사용
- 옵션은 2가지를 사용
  - -15 또는 -s SIGTERM 또는 -TERM
  - -9 또는 -s SIGKILL 또는 -KILL
- -15는 기본값으로 프로세스에 TERM 신호를 보내고 TERM 신호를 받은 프로세스는 종료에 필요한 작업을 수행한다
  - 임시로 생성한 파일을 삭제하거나 스프링 빈의 제거 처리를 하는 작업을 수행
- -9 옵션을 이요하면 프로세스를 강제로 종료한다
  - 수행하는 정리 작업을 할 수 없기 때문에 주의해서 사용해야 한다
  - -15 옵션으로 여러 차례 종료를 시도했음에도 프로세스가 종료되지 않을 때 -9 옵션을 사용하는 것이 좋음

## 백그라운드 프로세스

- tail, top, vi 처럼 서버에 접속한 뒤 터미널에서 실행하는 프로그램은 기본적으로 포그라운드(foreground) 프로세스로 실행된다
  - 터미널에 연결된 프로세스로 키보드나 스크린을 통해 사용자와 상호작용
  - 사용자와 터미널의 연결이 끊기면 종료됨
- 백그라운드 프로세스는 터미널과 연결되어 있지 않으므로 키보드나 스크린을 통해 사용자와 상호작용할 수 없음
  - 리눅스에서 백그라운드로 실행하려면 명령어 뒤에 & 를 붙이면 됨
  - java -Dserver.port=9000 -jar server.jar &
- 사용자가 로그아웃하면 터미널에서 실행한 백그라운드 프로세스가 함께 종료될 수 있다
  - nohup 명령어와 &를 함께 사용
  - nohup java -Dserver.port=9000 -jar server.jar &
- nohup 명령어로 실행한 프로세스가 콘솔에 출력하는 내용은 기본적으로 nohup.out 파일에 기록되고 다른 파일에 기록하고 싶다면 리디렉션을 사용하면 된다
  - nohup java -Dserver.port=9000 -jar server.jar > server.log 2>&1 &
- 2>&1
  - `2`: 표준 오류(System.err.println)
  - `>`: 리디렉션 연산
  - `&1`: 표준 출력
  - 표준 오류를 표준 출력과 동일한 경로로 전달하라는 의미

## 디스크 용량 관리

- 디스크 사용률이 높다는 알림을 받으면 즉시 파일 삭제 같은 조치를 해야 함
- 리눅스에서는 df 명령어를 사용해서 어떤 파티션의 사용률이 높은지 확인할 수 있음
  - -h 옵션을 붙이면 용량이 바이트 단위가 아닌 MB, GB 단위로 표시되어 쉽게 확인할 수 있음
  - df -h
- 삭제 대상을 찾을 때는 어떤 디렉토리가 많은 용량을 차지하는지 확인해야 함
  - du , disk usage 명령어 사용
  - du -sh ./*
  - -s 옵션을 사용하면 하위 디렉토리의 용량 합과 파일의 크기를 보여주고 -h 옵션은 바이트 대신 G, B 사용한다
- find 명령어를 사용하면 일정 기간이 지난 파일을 손쉽게 찾아서 삭제할 수 있다
  - find ./logs -mtime +29 -type f -delete
  - logs 디렉토리에서 30일 이전 파일을 삭제하고 싶을 경우
- 한 디렉토리에 저장되는 파일 개수에도 주읭해야 함
- 파일 개수가 증가하면 어느 시점부터 해당 디렉토리에 대한 파일 탐색 속도가 급격히 느려짐
- 문제가 발생하지 않으려면 한 디렉토리에 저장하는 파일 개수를 일정 개수 이하로 제한해야 함
- 일자나, 시간 기준으로 폴더를 생성하는 것

## 파일 디스크립터 제한

- 프로세스는 데이터 입출력이 필요할 때 OS로부터 파일 디스크립터(PD)를 할당받는다
  - 파일 입출력이나 소켓을 이용한 네트워크 입출력을 처리할 때 PD를 할당받아 사용
- OS는 사용자나 시스템 수전에서 생성할 수 있는 파일 디스크립터 개수를 제한함
- 사용자의 파일 디스크립터 개수 제한이 1024개라면 프로세스는 파일과 소켓을 합쳐 1024개를 초과해서 열 수 없음
  - Too Many Open Files 오류 메시지
- 트래픽 증가에 맞춰 미리 파일 디스크립터 개수 제한을 확인하고 늘려야 함
- ulimit -a 명령어로 사용자의 파일 디스크립터 개수 제한을 확인할 수 있음
  - open files 가 파일 디스크립터 개수 제한
  - ulimit -n으로도 확인 가능
- 기본 파일 디스크립터 제한을 변경하고 싶다면 /etc/security/limits.conf 파일을 수정함

```text
* soft nofile 100000
* hard nofile 100000
```

- 맨 앞의 *은 모든 사용자에 적용한다는 뜻
- nofile은 파일 디스크립터 개수를 의미
- soft와 hard는 각각 사용자의 기본 값과 설정할 수 있는 최대 값을 지정함
- 프로세스는 soft로 지정한 값을 기본으로 사용하고 부족할 경우 hard로 지정한 값까지 사용할 수 있음
- systemd로 실행되는 서비스는 ulimit이나 limits.conf 파일에 설정한 값을 사용하지 않고 /etc/systemd/system.conf 파일에 있는
DefaultLimitNOFILE 값을 서비스의 기본 파일 디스크립터 제한 값으로 사용함

## 크론으로 스케줄링하기

- 크론은 리눅스를 포함한 유닉스 계열 OS의 시간 기반 스케줄러
- 크론탭에 정의된 작업 목록을 조회할 때는 crontab -l 명령어를 사용함
- 크론탭은 crontab -e 명령어로 설정함
- `* * * * *`
  - 1번째 * : 분(0-59)
  - 2번째 * : 시(0-23)
  - 3번째 * : 월의 일(1-31)
  - 4번째 * : 월(1-12)
  - 5번째 * : 요일(0-6, 0이 일요일, 6이 토요일)
- 0 0 * * *
  - 매일 0시 0분
- 30 1 1 * *
  - 매월 1일 1시 30분
- 5 4 * * 0
  - 매주 일요일 4시 5분
- 콤마로 구분해서 개별 값을 지정할 수도 있음
- 0 1,2,3 * * *
  - 매일 1시, 2시, 3시
- 0, 30 5 * * *
  - 매일 5시, 5시 30분
- 구간을 지정할 때는 - 를 사용함
- 30 1-3 * * *
  - 매일 1시에서 3시의 매시 30분(1시 30분, 2시 30분, 3시 30분)
- 슬래시를 이용해서 시간 간격을 지정할 수 있음
- */10 1 * * *
  - 매일 1시 0분 부터 1시 50분까지 10분 간격으로
- 0 */2 * * *
  - 매일 2시 0분, 4시 0분 과 같이 2시간 간격으로

## alias 등록하기

- alias는 2가지 방식으로 등록할 수 있음
- 현재 터미널 세션에만 적용하는 방식
  - alias 명령어
- 로그인할 때 자동으로 alias를 적용하고 싶다면 쉘의 구성 파일에 alias를 등록하면 됨
  - 홈 디렉토리에 위치한 .bashrc 파일
- .bash_profile 파일은 사용자가 로그인할 때 한 번 실행되기에 PATH처럼 전체 세션에 필요한 환경 변수를 설정하고
.bashrc 파일은 새로운 bash 쉘을 시작하거나 터미널 창을 열 때 실행되기에 별칭과 같이 세션마다 적용할 것을 설정함

## 네트워크 정보 확인

### IP 정보 확인하기

- ifconfig 명령어를 사용함
- eth0는 일반적인 네트워크 인터페이스고 lo는 로컬 루프백 인터페이스

### nc 명령어로 연결 확인하기

- nc -z -v www.daum.net 443

### netstat 명령어로 포트 사용 확인

- netstat -lputn
  - -l: 리스닝 서버 소켓을 출력
  - -p: 소켓을 사용하는 PID/프로그램 이름을 출력
  - -u: UDP 소켓을 출력
  - -t: TCP 소켓을 출력
  - -n: 포트나 주소를 숫자로 출력
