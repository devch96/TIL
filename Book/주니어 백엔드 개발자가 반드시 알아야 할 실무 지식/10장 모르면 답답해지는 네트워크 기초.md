# 모르면 답답해지는 네트워크 기초

--------

## 네트워크 기초를 모르면

- 외부 API를 호출할 서버는 2개의 공인 IP와 연결되어 있었음
- 하나는 외부에서 서버에 연결할 때 사용하는 IP고 다른 하나는 서버에서 외부로 나갈 때 사용하는 IP
- 후자의 IP를 외부 업체에 공유했어야 했는데 전자의 IP를 알려줘서 연결이 안 됐던 것
- 서버 개발자가 네트워크 엔지니어만큼 네트워크 관련 지식을 깊이 있게 알 필요는 없으나 네트워크 지식이 전무하면 네트웤 ㅡ관련 문제가
생겼을 때 쉽게 해결할 수 있는 문제도 오랜 시간 동안 처리하지 못하게 됨
- 기본적인 지식은 필요

-------

## 노드, 네트워크, 라우터

- 데이터를 송수신하는 모든 장치를 노드(node)라고 표현함
  - 휴대폰, 노트북, 서버 장비 등이 노드
- 노드가 서로 데이터를 주고받기 위해 연결된 시스템을 네트워크라고 함
- 패킷
  - 노드가 네트워크를 통해 전송하는 데이터의 단위
  - 헤더와 페이로드로 구성되며 헤더는 패킷의 발신자와 수신자 정보를 포함하고 페이로드에는 데이터가 포함됨
  - 데이터는 일정 크기를 가진 여러 패킷으로 나뉘어 전송됨
- 서로 다른 네트워크에 속한 노드는 직접 연결해서 패킷을 송수신할 수 없기에 사용되는 것이 라우터
- 라우터는 네트워크 간에 패킷을 전송하는 역할
- 두 노드 간에는 다양한 라우터 이동 경로가 존재함

------

## IP 주소와 도메인

- 노드에 패킷을 전송할 때에도 주소를 사용함
- 네트워크에서 각 노드를 구분하기 위해 사용하는 주소를 IP 주소라고 함
- 각 노드의 IP 주소를 기억하기 쉽지 않기에 이름을 붙이는데 이것이 도메인
- 도메인 이름과 IP 주소로 변환하는 체계가 (DNS, Domain Name System)
- 도메인 이름은 계층 구조를 갖으며 계층은 점(.)으로 구분되고 오른쪽이 상위 계층, 왼쪽이 하위 계층
- 도메인 이름에 해당하는 IP 주소는 DNS 서버를 통해 확인함
  - www.naver.com을 브라우저에 입력하면 브라우저는 DNS 서버에서 IP 주소를 물어보고 응답받은 IP 주소로 패킷을 전송함

### 고정 IP와 동적 IP

- 동일 네트워크 상에서 각 노드는 서로 다른 IP 주소를 가져야 함
  - IP 주소를 사용해서 패킷을 전송할 노드를 선택하기 때문
- 노드의 IP 주소는 2가지 방식으로 지정함
- 고정 IP는 노드가 고정된 IP를 갖음
  - 서버 IP가 대표적
- 동적 IP는 노드가 네트워크에 연결할 때마다 IP를 할당함

### 공인 IP와 사설 IP

- 공인 IP 주소는 인터넷에 접속하는 모든 네트워크에 적용되는 주소이며 퍼블릭 IP 주소라고 함
- 네트워크 내부에만 적용되는 사설 IP 주소도 있음
- 사설 IP 주소는 특정 네트워크에 속한 노드에 할당하는 주소로 네트워크 외부에서 접근할 수 없음
- 사설 IP 대역
  - 192.168.x.x
  - 10.x.x.x
  - 172.16.x.x ~ 172.31.x.x

--------

## NAT

- NAT(Network Address Translation)는 네트워크 주소를 변환하는 기술
- 인터넷에 연결하려면 내부에서 사용하는 사설 IP와 인터넷에서 사용하는 공인 IP 주소 간의 변환이 필요한데 NAT가 이 변환을 담당함
- NAT는 주로 인터넷에 연결된 라우터 같은 네트워크 장비가 담당함
- 라우터는 내부 네트워크에서 나가는 패킷의 사설 IP를 공인 IP로 변환하는데 소스 IP의 주소를 변환한다고 해서 이를 SNAT(Source NAT)이라고 함
- 공인 IP로 들어온 패킷의 목적지를 사설 IP로 변환하기도 하는데 목적지 IP의 주소를 변환한다고 해서 이를 DNAT(Destination NAT)이라고 함
- 일반적으로 네트워크를 구성할 때 보안, 이중화 등을 고려해 서버 노드는 공인 IP가 아닌 사설 IP 주소를 갖음
- 공인 IP 주소는 네트워크 연결을 관리하는 장비(라우더, 방화벽 등)에 할당함
- 해당 장비는 DNAT를 이용해서 공인 IP로 들어온 패킷을 사설 IP를 가진 서버 노드에 전송

-------

## VPN

- 서버 네트워크에 존재하는 노드는 사설 IP를 사용함
- 외부 네트워크에서는 사설 IP에 직접 접근할 수 없음
- 서버 네트워크에 구성된 노드에 접근할 수 있어야 하는데 안전한 방법이 VPN(Virtual Private Network)
- VPN은 인터넷과 같은 공용 네트워크에서 서로 다른 네트워크 간에 암호화된 연결을 제공함
- 두 네트워크는 마치 하나의 사설 네트워크에 존재하는 것처럼 연결될 수 있음

-------

## 프로토콜과 TCP, UDP, QUIC

- 네트워크 상에서 두 노드가 데이터를 주고받기 위해 정의한 규칙을 프로토콜이라고 함
- 네트워크는 여러 계층으로 구성되며 각 계층마다 사용하는 프로토콜이 존재함
- 개발자는 주로 전송 계층과 애플리케이션 계층의 프로토콜을 사용함
- 전송 계층에서 사용하는 프로토콜에는 TCP와 UDP가 있음
- TCP (Transmission Control Protocol)는 연결 기반 프로토콜
  - 통화를 하기 위해 한 명은 전화를 걸고 한 사람은 전화를 받은 뒤에 대화를 주고 받는 것처럼
  먼저 연결을 맺은 뒤에 데이터를 주고 받음
  - 두 노드가 연결을 맺기 위한 과정을 3-Way-Handshake라고 부름
- TCP의 장점은 신뢰성에 있음
  - 패킷 순서를 보장하고 패킷이 유실될 경우 재전송하는 기능을 제공하고 있어 안정적으로 데이터를 전송할 수 있음
  - 애플리케이션 계층의 HTTP, SMTP와 같은 많은 프로토콜이 TCP를 기반으로 동작함
- TCP가 전송을 보장하기 위해 사용하는 시퀀스 번호, 확인 응답, 재전송 등이 추가되면서 전송 속도는 UDP 대비 상대적으로 느려짐
- UDP(User Datagram Protocol)는 연결 과정 없이 바로 데이터를 전송함
  - 데이터가 정상적으로 전송됐는지 알 수 없고 순서를 보장하지도 않음
  - 데이터 유실과 같은 상황이 발생할 수 있다고 가정하고 개발해야 함
- UDP는 응답 확인이나 패킷 정렬을 안하기 때문에 전송 속도는 TCP 대비 빠름
  - DNS, VoIP, 게임 등 사용함
- QUIC은 UDP를 기반으로 함
- TCP의 연결 관리 기능을 QUIC 프로토콜 수준에서 제공함
  - QUIC은 데이터에 연결 ID를 포함시키는데 이 연결 ID를 이요해서 두 노드 간의 연결을 유지함
- QUIC은 TLS를 통합함
  - 패킷을 기본적으로 암호화하여 전송함
  - TCP 기준의 HTTPS는 TCP 연결을 위한 3-Way Handshake와 TLS 연결을 위한 TLS Handshake를 진행해서 여러 차례 통신을 한 뒤에
  연결이 수립되는데 QUIC는 TLS를 통합함으로써 이 과정을 단축함
- 크롬, 에지, 사파리 등 주요 브라우저는 이미 HTTP/3를 지원함
